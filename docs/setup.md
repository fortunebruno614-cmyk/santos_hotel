# Setup — Santo Hotel (for teammates)

Get the Next.js app + PostgreSQL + Prisma running locally in ~5 minutes.

## Prerequisites

- Node.js 20+ and npm 10+
- PostgreSQL 16 via **Docker** (recommended) or local Homebrew
- Git

## Option A — Docker Postgres (recommended; matches the committed `.env`)

```bash
git clone https://github.com/fortunebruno614-cmyk/santos_hotel.git
cd santos_hotel
npm install                 # also runs `prisma generate` (postinstall)
docker compose up -d        # starts postgres on 127.0.0.1:5432
npm run db:migrate          # apply committed migrations
npm run db:smoke            # → "Database connection OK. Hotel rows: 0"
npm run dev                 # http://localhost:3000
```

No env file needed: the committed `.env` already points at the Docker credentials
(`santos` / `santos`, dev-only — see `docker-compose.yml`).

## Option B — Homebrew Postgres (per-machine override)

```bash
brew services start postgresql@14
createdb santos_hotel
cp .env.example .env.local  # then edit the URL, see below
npm install
npm run db:migrate
npm run db:smoke
npm run dev
```

Homebrew's default superuser is your macOS username with trust auth, so `.env.local`:

```env
DATABASE_URL="postgresql://YOUR_MAC_USERNAME@127.0.0.1:5432/santos_hotel"
```

`.env.local` is git-ignored and takes priority over `.env` (same rule as Next.js).

## Logins / credentials

| What | Value |
| ---- | ----- |
| Shared dev DB (Docker) | user `santos` / password `santos` / db `santos_hotel` @ `127.0.0.1:5432` |
| Homebrew DB (this repo's author) | user `mac` / no password / db `santos_hotel` @ `127.0.0.1:5432` |
| App user login | **not implemented yet** — accounts arrive in pipeline phase P3 (Auth & Authorization). No `users` table exists. |

These are local development credentials only. **Never put real secrets or production
credentials in `.env` / `.env.local`.**

## Env file rules

| File | Tracked | Purpose |
| ---- | ------- | ------- |
| `.env.example` | yes | template showing both DB options |
| `.env` | yes | shared dev baseline (Docker creds, no secrets) |
| `.env.local` | no | your machine's overrides; highest priority |

## Scripts

| Script | Purpose |
| ------ | ------- |
| `npm run dev` | Next.js dev server |
| `npm run build` / `start` | production build / serve |
| `npm run lint` / `typecheck` | ESLint / `next typegen && tsc --noEmit` |
| `npm run db:migrate` | create + apply a migration from schema changes |
| `npm run db:deploy` | apply committed migrations (CI/staging/prod) |
| `npm run db:reset` | drop, re-migrate and re-seed the dev DB |
| `npm run db:seed` | load development seed data (idempotent) |
| `npm run db:integrity` | run DB constraint/integrity checks |
| `npm run db:studio` | Prisma Studio |
| `npm run db:smoke` | DB connectivity check |
| `npm run db:dump` / `db:restore` | snapshot / restore dev data (see `docs/DB_AND_STORAGE.md`) |

## Prisma 7 notes

- Config: `prisma7.config.ts` (loads `.env.local` then `.env` via `dotenv`).
- Client output: `src/generated/prisma/` (git-ignored, generated by `postinstall`).
- Runtime uses the `@prisma/adapter-pg` driver adapter — see `src/lib/prisma.ts`.
- Version pinned to **7.10.0** (npm's `latest` is an 8.0 RC with a different CLI).

## Troubleshooting

- **`Address already in use` on 5432** — stop one server: `brew services stop postgresql@14`
  before `docker compose up -d`, or vice versa.
- **`role "santos" does not exist`** — you're on the committed `.env` while running
  Homebrew Postgres. Create `.env.local` with your own role (Option B).
- **`pg_dump: command not found`** — install client tools: `brew install libpq` (then
  `brew link --force libpq`) or `brew install postgresql@14`.
- **Prisma asks for consent on reset** — dev DB was created manually; run
  `npm run db:reset` interactively and confirm.
